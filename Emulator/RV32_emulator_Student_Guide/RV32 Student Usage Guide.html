2 · Set up your lab

Use the application supplied by your instructor when available. You do not need a separate RISC-V assembler or compiler to write and run assembly in rv32.

Windows

  1. Extract the supplied rv32-windows-x64.zip into a folder you can write to.
  2. Keep the entire extracted folder together, including the Qt DLLs and platforms folder.
  3. Double-click rv32-gui.exe.

Linux

If rv32 is already installed, open it from the applications menu or run rv32-gui. If given an AppImage and the repository’s installer, run:

bash /path/to/install.sh ~/Downloads/rv32-x86_64.AppImage

The installer installs under your user account, without sudo, and unpacks the AppImage to avoid a FUSE dependency. Use the actual paths to your downloaded files. A standalone AppImage can also run with chmod +x rv32-x86_64.AppImage followed by ./rv32-x86_64.AppImage when FUSE support is available.

Using an existing source build

From the repository folder, launch ./build/debug/rv32-gui (or the corresponding release build). Building the application is only necessary if your instructor asks for it; the repository’s docs/building.md covers that workflow.

3 · Run your first program

Open examples/first_steps.s, or create a new file with Ctrl+N and enter the program below. Save it as first_steps.s.

# First lab: add, store, and load
        .data
result: .word 0
        .text
        .globl _start
_start:
        li a0, 5
        li a1, 3
        add a2, a0, a1
        la t0, result
        sw a2, 0(t0)
        lw a3, 0(t0)
        ebreak
  1. Press F5 · Assemble. Resolve any errors before continuing. A note about la expanding into two instructions is expected.
  2. Press F8 · Step five times from the newly assembled state. The pipeline must fill before the first instruction commits; a0 then becomes 5.
  3. Continue stepping. Watch a1 become 3, then a2 become 8. la takes two machine instructions even though it occupies one source line.
  4. Select Memory. When sw commits, the word at data address 0 becomes 00000008. When lw commits, a3 becomes 8.
  5. Press F9 · Run to finish. ebreak stops the program intentionally.
Check at the endExpected value
a0 / x105
a1 / x113
a2 / x12 and a3 / x138 (0x00000008)
t0 / x50: the data address of result
DMEM address 000000008

Try it: change 5 to 12, save, and press F5 then F9. Both a2 and a3 should be 15. Pressing Reset alone does not assemble your edits.

4 · Read the machine state

The first program after its load has committed. Address 0 in data memory contains 00000008.

PanelHow to use it
RegistersMatch ABI names such as a0 with numbered names such as x10. Hex and signed decimal show the same 32 bits; FFFFFFFF is −1 in signed decimal. The last written register is highlighted.
MemoryRead a cell using row address + column offset. In row 00000010, column +4 is byte address 0x14. Each cell is one 32-bit word. You can edit values in hex.
EncodingInspect bitfields and the instruction’s effect. It follows write-back while stepping or the source caret when you select a line. Compressed instructions also show their base instruction.
SymbolsFind the value and address space of labels. result belongs to Data; _start belongs to Text.
ConsoleRead bytes sent to the UART. Arithmetic alone produces no console output.
DevicesInspect and operate attached inputs, outputs, and memory blocks.

Separate memories, shared-looking addresses

IMEM holds instructions; DMEM holds data. Both start at numeric address 0, but they are different storage. lw and sw access data memory or peripherals, never instruction memory. Use la t0, result for a data label, and j or call for a code label.

Word accesses need addresses divisible by 4; halfword accesses need addresses divisible by 2. The machine is little-endian. A word 0x12345678 occupies bytes 78, 56, 34, 12 at increasing addresses.

5 · Debug a loop

Open examples/sum_loop.s and press F5. The loop adds 1 + 2 + 3 + 4 + 5 into a0.

  1. Click the editor margin beside add a0, a0, t0 to set a breakpoint. Use an executable line rather than a blank line.
  2. Press F9 to reach the breakpoint. Inspect the accumulator and loop counter before advancing.
  3. Use F8 to advance cycles until the add commits. Use F6 to undo cycles and watch the committed change reverse. F6 is disabled when no cycle history remains.
  4. Click the same margin to remove the breakpoint, then F9 to finish. Expect a0 = 15 and t0 = 6.
  5. Press F4 to restart the loaded program. Reset keeps breakpoints; remove them if you want an uninterrupted run.

A loop in flight. The Pipeline tab shows stage occupancy and an instruction-by-cycle history.

IF fetches, ID decodes, EX represents execution and target calculation, MEM represents data access, and WB commits the instruction. The yellow source line marks write-back. Resolved branches are green when taken and red when they fall through.

Interpret timing carefully: this is a teaching visualization, with no hazards, stalls, or forwarding. The engine commits a whole instruction at WB; branch outcomes also resolve there. The panel’s cycle count differs from the program-visible counters. Do not use it to measure FPGA cycle timing or CPI.

To step over a function in the GUI, place a breakpoint on the executable line after its call and run to it. F9 again interrupts a running program.

6 · Write code and fix mistakes

Type two letters of a mnemonic, or press Ctrl+Space, to open suggestions. Tab / Shift+Tab cycle choices; Enter accepts; Esc closes the suggestions. Grey operand hints are placeholders, not saved text. Enter registers, commas, and values yourself.

SymptomWhat to check or change
Undefined symbolCompare spelling and case with the label definition. Click the diagnostic to jump to its location.
Immediate out of rangeaddi accepts −2048 through 2047. Use li to load a larger constant, then a register arithmetic instruction where appropriate.
A call targets a data symbolPut executable code in .text. Use la for the address of an object in .data.
Misaligned load/storeFor lw/sw, check that the effective address is a multiple of 4. Avoid placing a word immediately after an unaligned byte or string without padding/alignment.
Red overflow markingsThe program exceeds IMEM. Increase the configured memory if your lab permits, or reduce the program; reassemble. Check DMEM overflow messages too.
Illegal instruction or fetch faultCheck the stopping PC, jump targets, and whether execution fell beyond your code. End a simple exercise with ebreak.
Peripheral access faultVerify that the board file attaches a device at the address your program accesses.
No register changes after a stepF8 advances one pipeline cycle. Wait for WB; also remember that writes to x0 are discarded.
Old behavior after editingSave, then press F5 successfully. A failed assembly leaves the previously loaded program intact.
An endless loopInterrupt with F9, set a breakpoint at the branch, and inspect its inputs. Confirm the counter advances toward the exit condition.
No console textOpen Console and verify a store to the UART transmit address. This tool does not provide another simulator’s print ecall services.

A repeatable debugging method

  1. Write down the expected register or memory value at a particular line.
  2. Break before the region that produces it.
  3. Step until the first difference appears, inspecting operands and addresses.
  4. Use Back to revisit that change, fix the source, then save and assemble again.

Practice: in a copy of the loop, change loop to lop in the branch. Assemble, follow the diagnostic, correct it, and reassemble.

7 · Console and peripherals

Open examples/uart.s, assemble, run, and select Console. It writes ASCII 65 followed by ASCII 10, so the output is A followed by a newline.

# Print A and a newline on the default machine
        .text
        .globl _start
_start:
        li t0, 0xffff0000
        li a0, 65
        sb a0, 0(t0)
        li a0, 10
        sb a0, 0(t0)
        ebreak
Default addressPurpose
0xFFFF0000UART: store a byte at +0 to transmit; status at +4.
0xFFFF0010LED output register.
0xFFFF0020Switch input register.
0xFFFF0030mtime timer value.
0xFFFF0040mtimecmp timer deadline.
0xFFFF0050 / 0xFFFF0054Software / external interrupt request registers.

Try a board configuration

  1. Choose File → Load peripherals… and open the included examples/board.toml. This replaces the attached devices and specifies memory sizes.
  2. Open switches_leds.s and assemble. In Devices, inspect the switches; the supplied board starts them at binary 1010 (decimal 10).
  3. Run. Expect a0 = 10 and the corresponding LED value. The program reads once and stops.
  4. Change the switches, reset, and run again to sample the new value. Switch inputs survive reset.
  5. Use File → Save peripherals… to save a configuration you need to reproduce later.

Other devices include buttons, numeric inputs, displays, RAM/ROM blocks, custom registers, and a multiplier function device. Use the configuration supplied for the assignment; addresses may differ from the defaults. Select a RAM/ROM block for its own Load .mem and Export .mem controls.

For interrupt labs, start with the repository’s examples/timer.s. Install a handler and enable the relevant interrupt before expecting it to run. Timer and instruction counters are not wall-clock or FPGA timing measurements.

8 · Export files for your hardware lab

An assembly source file is editable code. A .mem file is a memory image. Keep your .s file even after exporting.

  1. Load the assignment’s board configuration and set the required IMEM/DMEM sizes in the Memory tab. Save your source and press F5. Resolve errors and overflow markings.
  2. Choose Generate on the toolbar, press Ctrl+E, or use File → Generate .mem….
  3. Choose the destination folder and base name. Select imem and dmem as needed. With base name lab01, the outputs are lab01_imem.mem and lab01_dmem.mem. The default base name is rv32.
  4. Use disassembly comments only if your receiving workflow accepts them. For a plain image, leave annotation unchecked.
  5. Press Export. Match each displayed depth to the hardware memory: 16,384 bytes = 4,096 words, each 32 bits wide.

Which export do you need?

ActionData written
Generate / Ctrl+EThe most recently assembled program and its initial .data contents, padded to the configured memory depths.
Memory → Export .mem…The current DMEM contents, including changes made during execution or manual editing.
Devices → selected block → Export .mem…That RAM/ROM block’s current image, padded to the block’s own size.

For the first example, Generate writes result = 0 because that is the source initializer. After running, exporting the Memory tab captures result = 8. Generate does not automatically assemble later edits.

Read the file correctly

Each line contains one 32-bit hexadecimal word. Counting the first line as index 0, line index n corresponds to byte address 4 × n. Compressed instructions are packed into this word stream; one file line is not necessarily one instruction.

reg [31:0] imem [0:4095];
initial $readmemh("lab01_imem.mem", imem);

This is a Verilog simulation initialization example. Use the import/initialization procedure specified for your FPGA IP and lab. In a 32-bit Block Memory Generator, a 16 KB image corresponds to Write Depth 4096. Confirm the required file format for that flow; changing a filename extension does not convert formats.

CLI difference: rv32 asm exports only used memory by default. Include --pad for full-depth images, and the same --devices board.toml configuration when using custom memory sizes.

9 · Use the terminal tools

Run these commands from your working exercise folder. Replace rv32 with the path to the executable if it is not on PATH. On Windows PowerShell, use .\rv32.exe when it is in the current directory.

rv32 run first_steps.s
rv32 run first_steps.s --trace
rv32 run sum_loop.s --limit 1000
rv32 asm first_steps.s --pad -o lab01_imem.mem --dmem lab01_dmem.mem
rv32 dis lab01_imem.mem
rv32 run switches_leds.s --devices board.toml
rv32 asm first_steps.s --pad --devices board.toml
rv32 dbg sum_loop.s

The trace lists machine instructions and their effects, so a pseudo-instruction may produce multiple lines. The default run limit is 1,000,000 instructions. A limit stop means execution has not necessarily completed. A padded IMEM disassembly can include unused zero-filled memory after the program.

Before recording or handing in results

  • Save the source and assemble it successfully.
  • Run from a known initial state using the intended board and inputs.
  • Check the requested registers, memory addresses, and output against your prediction.
  • Record the input values, board configuration, expected result, and observed result.
  • When asked for hardware images, export with the required sizes and inspect the filenames. Follow your instructor’s actual submission requirements.

Architecture facts to remember

This tool supports RV32 integer instructions, multiply/divide, compressed instructions, machine CSRs, and fence.i. It has separate instruction/data memory and machine mode only. It does not load ELF programs or provide floating-point instructions. x0 always reads as zero. li, la, and call are pseudo-instructions. Compression is explicit: ordinary instructions do not automatically become c.* instructions. ecall raises an exception; use the provided UART method for simple output.
